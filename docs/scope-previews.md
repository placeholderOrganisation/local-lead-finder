# Scope-tool design previews — runbook

How the "Scope your site" design previews work, and **how to update the base design
and everything connected to it**. Read this before touching the template, the
`mockup-scope` bucket/worker, or the seed/deploy scripts.

## What this is

The Mintek site's **"Scope your site"** tool (in the `professionals` repo,
`vite-mintek/src/components/service/ScopeTool.jsx`) ends its result screen with **three
design directions**. Those previews are hosted here, on Cloudflare, reusing the same
Worker + R2 model as the outreach mockups. The same previews are shareable links you can
also use for cold outreach.

## The one idea that explains everything

There is **one shared template** and **many small content files**. The template (the
actual *design*) lives once at the bucket root. Each preview is just a `config.json` that
the template fills itself with. So:

- **Design = the template.** `template/accountant/components/designs/{emerald,dark,soft}.tsx`
  are the three themes. Editing these changes the look of **every** preview at once.
- **Content = per-leaf `config.json`.** Generated by `data/scope-previews/leaves.js`
  (headline, services, FAQ, example business name). Content, never layout.

A "leaf" = `businessType` × `mainJob` (e.g. `salon-bookings`) — the two scope-tool answers
that change design. 6 × 5 = **30 leaves**. Each leaf is served at
`https://mockup-scope.<subdomain>.workers.dev/{leaf}/` and screenshotted into
`{leaf}/thumb-{1,2,3}.webp`.

Theme ↔ `?design=` mapping: **1 = Emerald, 2 = Midnight/dark, 3 = Soft** (see
`template/accountant/lib/design.tsx`, which reads `?design=N` to pin a theme for shared links).

## Key files

| File | Role |
|---|---|
| `template/accountant/components/designs/{emerald,dark,soft}.tsx` | **The 3 base designs.** Edit these to change the look. |
| `template/accountant/lib/design.tsx` | Theme selection; reads `?design=1\|2\|3`. |
| `template/accountant/lib/site-config.ts` | The `config.json` shape the template expects. |
| `data/scope-previews/leaves.js` | Generates the 30 leaf **content** configs. |
| `scripts/deploy-site.mjs` | Builds + uploads the template, deploys the worker. |
| `scripts/seed-scope-previews.mjs` | Uploads configs + screenshots → thumbnails. |
| `workers/site/wrangler.toml` | `[env.scope]` → `mockup-scope` worker + bucket. |
| `workers/site/src/worker.js` | Serves SPA shell + `{leaf}/config.json` (env-agnostic; rarely changes). |

## HOW TO: update the base design

Editing `components/designs/*.tsx` updates the **live previews** but NOT the widget's
**thumbnails** (those are static screenshots). Always do both steps:

```bash
# 1. push the new template → all 30 live previews update within ~60s
npm run deploy:scope

# 2. re-screenshot so the widget thumbnails match the new design
npm run seed:scope
# (or a subset while iterating:  node scripts/seed-scope-previews.mjs --only salon-bookings)
```

`deploy:scope` = `deploy-site.mjs scope --template accountant` — it builds the accountant
template and deploys it to the **`mockup-scope`** bucket/worker.

### ⚠ Two buckets share this template — deploy each one you want updated

`template/accountant/` feeds **two separate deployments**:

- `npm run deploy:scope` → **`mockup-scope`** bucket (the 30 category previews for the tool)
- `npm run deploy:site -- accountant` → **`mockup-accountant`** bucket (per-lead outreach previews)

Editing a design component changes both, but each bucket only updates when **you deploy that
one**. If you want the outreach previews to match a design change, run the second deploy too.

## HOW TO: change preview content (copy)

Edit `data/scope-previews/leaves.js`:
- `TYPE_ARCHETYPES` — per-business-type example name, about, services, FAQ.
- `JOB_ANGLE` — per-main-job hero headline/sub + the feature surfaced first.

Then re-seed (no template deploy needed for content-only changes):

```bash
npm run seed:scope           # re-uploads all configs (+ re-screenshots)
```

To add themes or leaves: add a `designs/<name>.tsx` + extend the switch in
`site-app.tsx`/`design.tsx` (new theme), or extend `BUSINESS_TYPES`/`MAIN_JOBS` in
`leaves.js` (new leaves) — and keep them in sync with the widget's `QUESTIONS` values.

## Prerequisites

- `.env` here needs: `CLOUDFLARE_API_TOKEN`, `WORKERS_SUBDOMAIN`, and the `R2_*` keys.
- **Screenshots** need a launchable Chrome. The seed script uses your **system Chrome**
  (`channel: "chrome"`); puppeteer's bundled Chrome may not run on older macOS. Override with
  `PUPPETEER_EXECUTABLE_PATH=/path/to/Chrome` if needed. If no browser launches, configs still
  upload and the widget shows a themed fallback card (never a broken image) — but thumbnails
  won't refresh until screenshots succeed.

## The widget side (professionals repo — cross-reference)

- Component: `vite-mintek/src/components/service/ScopeDesigns.jsx`.
- Wired by env var `VITE_SCOPE_PREVIEW_BASE` (in `vite-mintek/.env`), e.g.
  `https://mockup-scope.mintek.workers.dev`. If unset, the section renders nothing.
- The widget builds the leaf as `` `${businessType}-${mainJob}` `` — **must match** the slug
  scheme in `leaves.js` (`leafSlug`). It requests `{leaf}/thumb-{1,2,3}.webp` and links to
  `{leaf}/?design={n}`. Missing thumbnail → themed fallback card, so unseeded leaves are safe.

## Cost

Same free stack as the original mockups. R2 has **no egress fees**; free tier covers 10 GB
storage / 1M writes / 10M reads per month (usage here is a few MB and dozens of objects).
Workers free plan = 100k requests/day. Screenshots run on **local** Chrome — Cloudflare
Browser Rendering (which bills) is **not** used. No surprise bill at normal lead volumes.
